01 / THE PROBLEM

Important context can hide inside a document.

Enterprise information is not always a clean body of searchable text. People may need to find an answer across documents while useful evidence lives in page structure, scanned images, charts, or other visual elements.

The project focused on internal document retrieval and analysis using internally hosted open-source language models. The product challenge was to make the information easier to query while bringing text-based retrieval and visual document analysis into the same workflow.

02 / MY CONTRIBUTION

Connected retrieval with document understanding.

My work included developing retrieval and analysis capabilities using RAG approaches, including the resume-described GRAG and CRAG methods, as well as self-query and text-to-query patterns. I also worked on OCR and image processing for document content such as charts and images.

My roleAI Engineer and Backend Developer, working on an enterprise document-intelligence platform.

04 / DESIGN CONSIDERATIONS

Make the result inspectable.

A

Retrieval is part of the product

Different query patterns can change what context is retrieved. The experience should make it possible to judge whether the returned material is relevant.

B

Visual content matters

OCR and image processing extend analysis beyond plain text, especially when information is contained in charts or scanned pages.

C

Deployment constraints shape choices

The use of internally hosted open-source models means model selection and operating context are part of the solution—not a detail to hide behind the interface.

D

Evaluation needs to be explicit

Retrieval relevance, answer grounding, and visual extraction quality are useful evaluation dimensions. Specific scores are not published here because none were included in the material reviewed.
