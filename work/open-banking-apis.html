01 / THE PROBLEM

API work has a discovery problem as well as a specification problem.

In an open-banking API platform, engineers need to find relevant API information and create or review specifications. These tasks depend on domain context and precise, structured output—two areas where a plain-language interface can help only if it brings the right information into the workflow.

02 / MY CONTRIBUTION

Applied generative AI to API search and specification workflows.

My work included AI-based search and capabilities for creating and reviewing OpenAPI YAML from user prompts. The approaches described include retrieval-augmented generation and few-shot learning.

Scope distinctionThe API search and OpenAPI capabilities are described as developed. Agentic API lifecycle management is exploration, not a shipped capability claim.

04 / PRODUCT JUDGMENT

Help with the work; keep the work inspectable.

A

Search should answer a task

API search is most valuable when it helps a developer make progress in a specific workflow, not merely return a chat response.

B

Structured output needs scrutiny

OpenAPI YAML is machine-readable. A polished-looking draft should not be mistaken for a validated contract.

C

Context affects usefulness

Retrieval and few-shot examples can shape what the system returns; their quality and relevance deserve evaluation.

D

Separate exploration from delivery

Agentic API lifecycle management was described as an area being explored, so this portfolio keeps it distinct from the capabilities developed.
