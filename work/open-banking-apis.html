01 / THE PROBLEM

APIs have a discovery challenge as well as a specification challenge.

In open banking ecosystems, engineering teams maintain hundreds of distinct microservices and REST endpoints covering accounts, payments, consent management, and transaction histories. Developers frequently spend hours searching documentation to locate reusable interfaces or constructing repetitive OpenAPI YAML specifications from scratch.

While generative AI can write boilerplate, open-banking contracts have strict syntax, validation, and security requirements. A specification authoring assistant is only useful if it grounds generation in verified schema patterns and keeps the generated output strictly inspectable.

MANUAL CATALOG LOOKUP

Path memorization & repetitive YAML

Engineers combed through hundreds of banking endpoints by exact path name and hand-authored repetitive OpenAPI 3.1 boilerplate and error schemas.

RAG + FEW-SHOT AUTHORING

Intent-driven search & validated contracts

Semantic RAG surfaces relevant catalog endpoints by developer task and drafts schema-validated OpenAPI YAML using curated few-shot examples.

02 / MY CONTRIBUTION

Applying generative AI to API discovery and contract authoring.

I engineered AI-assisted search and prompt-driven specification authoring modules for the platform:

  • Semantic API Discovery: Implemented natural-language vector search over API schemas and docstrings, allowing developers to query capabilities by intent rather than memorizing endpoint paths.
  • Few-Shot Prompt Engineering: Crafted high-precision prompt templates populated with verified OpenAPI 3.1 examples to enforce consistent casing, headers, error responses, and HTTP status codes.
  • Schema Validation Gate: Integrated automated YAML parsing and linting pipelines to verify structural correctness before presenting the output for human review.
Scope Distinction The API search and OpenAPI generation capabilities are fully developed. Agentic lifecycle management was an exploratory research area, not a claim of autonomous production deployment.

05 / EVIDENCE & LIMITS

This case study reflects developed prompt-to-OpenAPI capabilities. It does not claim autonomous end-to-end API deployment, universal specification acceptance without developer revision, or unverified commercial productivity metrics.
